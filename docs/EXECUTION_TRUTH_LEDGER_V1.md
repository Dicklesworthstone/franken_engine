## Purpose

Bind the historical JIT, AOT, tiering, Test262, performance, and claim records to the code paths and artifacts that actually exist. The ledger preserves useful scaffolding while preventing planning records, input-only hashes, synthetic timings, test-only paths, or observed failures from being promoted into production-success claims.

The evidence classes are facets, not a maturity ladder. A surface can be executable and simulated, or observed and test-only, without being production-wired.

## Classification vocabulary

| Class | Meaning |
|---|---|
| `executable` | A real parser, validator, runner, planner, benchmark, or runtime path executes rather than existing only as prose or a type declaration. |
| `observed` | A real run produced measurements or decisions. Observed does not imply that a target passed. |
| `planning_provenance` | The surface records plans, identities, guards, lineage, or future backend intent but is not itself the claimed executable output. |
| `production_wired` | The surface reaches the same native parse-lower-execute path used by shipped runtime orchestration, not merely a fixture or isolated model. |
| `simulated` | The implementation deliberately models the claimed operation without executing the real backend or effect. |
| `synthetic_estimate` | A duration, size, hash, or outcome is derived from a formula or label rather than measured from the claimed output. |
| `test_only` | The evidence is exercised by tests, CI, benchmarks, or audit tooling and is not itself a shipped runtime execution lane. |

- Git tracking state is part of reproducibility truth: an ignored working-tree artifact can support local diagnosis but cannot by itself support a fresh-clone observed claim.
- A local_optional proof retains its historical path and hash, is fully revalidated when present, and emits an explicit absence event when missing; it never substitutes for required or Git-tracked closure evidence.
- Observed performance and conformance failures remain valuable evidence; observed describes the measurement, not success against the target.
- Opportunity and relevance scores are ordinal 1-100 planning signals, not probabilities or measured effect sizes; S, M, L, and XL budgets describe relative engineering scope and exclude external-dependency latency.
- QuickJS- and V8-named native lanes are compatibility-era profile names, not bindings to those engines.

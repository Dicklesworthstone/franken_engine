## 🔒 Mutation Policy Enforcement

The shadow daemon implementation includes active enforcement to prevent:

- **Direct mutation commands**: br, git, rch, agent-mail, worker, queue
- **Shell escape attempts**: Command substitution with $() or backticks  
- **Dangerous flags**: --execute, --force, --auto, --yes
- **Indirect mutations**: Commands chained with mutation operations

All operator actions are validated before display and must remain advisory-only.

## 📊 Documentation Governance

Documentation claims are actively validated against gate status:

- **Aspirational claims** trigger validation failures
- **Premature capability claims** are blocked until gates are green
- **Advisory-only language** is enforced in user-facing documentation
- **Clear proof state communication** is required

The shadow daemon will be considered ready for capability promotion when:

1. **All adoption gates are 🟢 GREEN**

5. **Mutation policy enforcement remains active and tested**

Until these criteria are met, the shadow daemon **MUST** remain in advisory-only mode with appropriate documentation disclaimers.

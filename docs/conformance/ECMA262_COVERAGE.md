## Coverage budget

The aggregate `MUST`/`SHOULD`-clause budget for the ES2020 profile is
recorded in `crates/franken-engine/docs/CONFORMANCE_HARNESS_MANIFEST.md`
under the "ECMAScript baseline builtins" row:

| Bucket | Count | Source |
| --- | ---: | --- |
| `MUST` clauses | **1847** | Manifest scorecard row "ECMAScript baseline builtins" |
| `SHOULD` clauses | **423** | Manifest scorecard row "ECMAScript baseline builtins" |
| Tested (current) | 147 | Manifest scorecard, "Tested" column |
| Passing (current) | 124 | Manifest scorecard, "Passing" column |
| Aggregate score | **0.67** | Tracked separately as FIND-3 / `bd-u2n6w` |

The 0.67 score is well below the 0.95 promotion threshold codified in
[`ECMA262_CONFORMANCE_TARGET.md`](../ECMA262_CONFORMANCE_TARGET.md#compliance-threshold);
closing that gap is `bd-u2n6w` (FIND-3) and is **not** in scope for this
matrix. This matrix documents the SHAPE of current coverage, not the
target distribution. The phased plan that names the work required to
reach `≥ 0.95` lives in
[`MUST_COVERAGE_REMEDIATION_ROADMAP.md`](./MUST_COVERAGE_REMEDIATION_ROADMAP.md)
(also FIND-3 / `bd-u2n6w`) — it surfaces that the `0.67` figure itself
is opaque-by-construction (no derivable formula from the column inputs)
and that the dominant remediation surface is coverage (`+1608` new
tagged MUST cases), not test pass rate.

## Per-feature surface vs spec budget

For the per-feature spec areas covered by a dedicated harness, the
ratio of tagged `MUST` tests to the harness's *own* domain gives a
local saturation signal. The denominator is **not** the global 1847
MUST budget — that's spread across hundreds of §-clauses that have no
dedicated harness yet:

| Spec area | Harness `MUST` tags | Observation |
| --- | ---: | --- |
| §7 Abstract Operations | 13 | Thin: §7 enumerates dozens of MUST clauses across ToNumber/ToString/ToObject/etc. |
| §12.3.10 OptionalExpression | 19 | Dense for a single-section feature — covers chain semantics, short-circuit, mixed `?.` / `?.[ ]` / `?.( )`. |
| §13.3 / §14.1 Destructuring | 12 | Light vs the §13.3.{1,2,3} grammar surface. |
| §13.7 IterationStatement | 29 + 8 SHOULD | Currently the densest harness; 14 frontier-fail cases (`bd-bg9l1.27`). |
| §14.2 ArrowFunction | 22 | Tracks both grammar and `[[ThisMode]]` / no-`new` semantics. |
| §10.2.1 Strict Mode Code | 0 | **Empty tags** — see FIND-15 `bd-s2ubw`. |
| §12.2.9 TemplateLiteral | 15 + 3 SHOULD | Positive paths only — error-case tests missing (FIND-8 `bd-t2cgg`). |
| §27 Promises + async | 19 | Round-trip present; rejection-path error cases missing (FIND-21 `bd-hjfj1`). |
| §7.4 / §27.1 Iterator protocol | 13 | Custom `Symbol.iterator` cases incomplete (`bd-bg9l1.27`). |
